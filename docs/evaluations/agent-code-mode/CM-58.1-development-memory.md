# CM-58.1 Deterministic Reference Capability Safety Layer

## Status

CM-58.1 is a provider-free deterministic safety slice implemented against
baseline `8ad6a0493d2bfdd2f636d6dcfe832acc9878fb31`.

```text
provider calls: 0
prompt changes: none
planner/schema/registry changes: none
provider/repair changes: none
CM-57P changes: none
CM-58.2: not started
CM-57D: blocked
```

The layer is inserted between `plan_v2` and `enrich_context`:

```text
plan_v2
  -> capability_safety
  -> enrich_context
  -> workers
  -> merge_intent
```

It operates on the original request and the validated `SemanticPlan`. It does
not inspect planner prose, provider output, source contents, or renderer
state.

## Motivation

The CM-57P10 terminal rejection recorded 13 candidate gains, one protected
regression, and six unexpected reference tracks. The production semantic-plan
validator proves capability registration, category validity, uniqueness, and
parent closure, but it does not establish that a structurally valid
`track.reference` was requested by the user. CM-58.1 addresses only that
reference-capability admissibility gap. It does not attempt to improve general
planner quality.

## Frozen Policy

The policy version is:

```text
cm58.reference-admissibility.v1
```

Reference intent is classified deterministically from normalized original
request text as one of:

```text
explicitly_requested
explicitly_forbidden
unspecified
conflicting
```

Positive phrases are deliberately bounded to explicit reference/depth-track
language. Negative phrases are limited to explicit exclusion language. A
request containing independent positive and negative matches is conflicting
and fails closed. Bare depth indexing is not treated as a request for a
second reference track.

Only `track.reference` is governed. Other capabilities, report tasks, source
selection, section allocation, and typed-worker semantics remain unchanged.

## Deterministic Repairs

An explicitly requested reference capability is preserved. If reference is
unspecified or explicitly forbidden, each affected section task is repaired
without changing any other plan field or task ordering:

1. Remove `track.reference` when a normal track already exists.
2. Replace `track.reference` with `track.normal` when a curve binding depends
   on the reference parent.
3. Remove `track.reference` when an independent array/raster capability is
   present.
4. Fail with `reference_repair_would_empty_section` when removing the
   reference would leave no meaningful section content.

The transformed plan is revalidated with the existing
`validate_semantic_plan()` and fails with `reference_repair_invalid` if the
repair is not a valid registered capability plan. Conflicting intent fails
with `reference_intent_conflict`.

No repair reallocates a positive reference request between sections. Multiple
sections remain in their original order and keep their original goals,
summary, report task, requirements, constraints, unresolved requirements, and
source hints. The v1 policy does not infer which section should own a positive
reference request.

## Graph and Host Contract

Graph state stores only bounded `capability_safety` evidence: policy version,
classified intent, changed flag, action kind, section index, and bounded
reason. The original request and repaired plan are not copied into safety
evidence. Successful repairs project one non-retryable warning per action at
the `capability_safety` stage. Deterministic safety failures produce
`success=False`, no merged intent, zero workers, and one non-retryable
`capability_safety.<failure>` diagnostic.

The graph obtains the planner registry when available and uses the built-in
registry only for test doubles that do not expose one. No provider call is
made by the safety layer.

## Boundaries and Non-Goals

This slice does not modify planner prompts, `SemanticPlan`/`SectionTask`
schemas, capability declarations, provider adapters, program repair, source
discovery, enrichment, compiler behavior, routing, MCP, persistence, or
legacy compatibility. It does not add retries, fallback execution, section
allocation, channel inference, or reference rendering behavior.

The deterministic classifier is intentionally conservative and is not a
general natural-language intent parser. Its result is evidence for one
specified post-planner invariant, not production-level planner-quality proof.
