## Motivation

The CM-57P10 terminal rejection included a protected report-boundary failure:
the planner produced a `ReportTask` with no selected report capability for a
genuine report-wide request, while the P arm selected `report.standard`.
Existing structural planner validation permits an empty report capability
tuple. CM-58.2 adds the narrower deterministic invariant without reopening
the closed P-series.

## Request-Derived Intent

The classifier uses only the original request after deterministic NFKC,
casefold, punctuation-to-space, and repeated-whitespace normalization. It
does not retain normalized text or use planner-generated summaries, goals,
requirements, constraints, or section prose as authoritative evidence.

It returns exactly one of:

```text
report_only
section_only
mixed
unspecified
```

Bounded report-wide signals include report, cover, memo, brief, packet,
completion/interpretation/review summaries, heading/subtitle, preparer,
report/header fields, page settings, service title, output DPI, report/review
notes, and remarks. Bounded section-local signals include section, panel,
view, track, curve, image, waveform, raster, plot, and log-view/display
forms. Bare `title`, `summary`, `note`, `depth`, and `scale` do not force a
report classification.

The classifier is conservative and is not a general natural-language parser.
Unrecognized wording may remain `unspecified`; CM-58.2 fails closed rather
than guessing.

## Frozen Repair Policy

The only report capability used by v1 is the existing registry capability
`report.standard`. The registry and its metadata are unchanged.

For `report_only`, the layer requires a planner-created `ReportTask`, no
section tasks, and `report.standard` in a non-empty capability selection. An
empty selection is repaired by adding `report.standard` while preserving the
report goal, requirements, and constraints. A missing task fails with
`report_task_missing_for_explicit_report_intent`; planner-created section
work fails with `unexpected_section_work_for_report_only`.

For `mixed`, the layer requires both a planner-created report task and at
least one section task. An empty report selection gains `report.standard`;
missing report or section work fails with
`report_task_missing_for_mixed_intent` or
`section_task_missing_for_mixed_intent`. A non-empty report selection without
`report.standard` fails with
`report_standard_missing_from_nonempty_report_task`.

For `section_only`, a planner-created report task is removed when section work
remains, regardless of whether its capability selection is empty or already
contains `report.standard`. If removal would leave no work, the layer fails
with `report_removal_would_empty_plan`.

For `unspecified`, a valid non-empty report task and a missing report task
pass through. An empty report task fails with
`empty_report_task_with_unspecified_intent`, because the layer cannot know
whether to add or remove it.

CM-58.2 never synthesizes a missing `ReportTask`, creates section work,
deletes report-only section work, or appends `report.standard` to an
unsupported non-empty report capability set.

## Revalidation and Evidence

Every modified plan is rebuilt through `SemanticPlan.model_validate()` and
the existing `validate_semantic_plan()` before enrichment. Revalidation
failure is bounded as `report_boundary_repair_invalid`.

The original plan is immutable. Add repairs modify only
`ReportTask.capability_ids`; remove repairs modify only `SemanticPlan.report_task`.
Section order/content, report semantics, summary, unresolved requirements,
source hints, existing-section hints, goals, requirements, and constraints are
preserved.

Graph state stores only deterministic evidence: policy version, intent,
changed flag, action kind, and bounded action reason. It stores no request,
planner prose, path, provider response, timestamp, or secret. Successful
repairs emit one non-retryable warning per action at stage
`report_boundary_safety`. Safety failures return `success=False`, no merged
intent, zero workers, and one non-retryable
`report_boundary_safety.<failure>` diagnostic.

## P10 Regression Coverage

Tests cover the Aurora empty-report-capability class, valid report-only
controls, mixed report/section controls, and section-only spurious report
tasks. The case names remain test/documentation data only; production code
contains no P10-specific logic.

The key limitation remains that explicit report intent with a missing entire
report task fails closed. Reconstructing its goal and semantic requirements
would make this layer another planner, which is outside CM-58.2.
