# SI-V2R-BR2 Converter Compatibility

## Direct schema comparison

The pinned reference converter is run against the exact canonical schemas
generated by `SemanticIRV2` and `SemanticIRV2R`. The audit stores conversion
status, warnings, grammar hashes, byte sizes, and rule counts; it does not
commit the generated grammar body.

The comparison is descriptive. Grammar size is not treated as a reliability
measure, and a successful conversion is not a semantic model pass.

The provider-free reference execution completed for both schemas:

- SI-V2: `PASS`, 12,761 grammar bytes, 109 grammar rules;
- SI-V2R: `PASS`, 13,907 grammar bytes, 114 grammar rules.

The generated grammar bodies are represented only by SHA-256, byte count, and
rule count in `tests/fixtures/semantic_ir_v2r_br2/converter_audit.json`.

## Runtime-only invariants

The malformed matrix continues to distinguish JSON-Schema acceptance from
canonical Pydantic validation. Missing reference targets, duplicate semantic
IDs, invalid fill targets, blank collection items, and the requirement for
report or section work are canonical runtime rules rather than silently
attributed to the converter.

No grammar parser from the same pinned toolchain is available in this slice.
Consequently, the 24 gold objects are accounted for as `24/24` JSON-Schema and
canonical-model accepts, while grammar representability is
`NOT_EVALUABLE` rather than inferred. The same artifact records `9/11`
malformed payloads accepted by JSON Schema and `0/11` accepted by the
canonical model, preserving the runtime-only distinction.
